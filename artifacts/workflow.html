How the auto-grader works

Input: question, model answer, rubric (or none), student answer. Output: marks with evidence, and feedback for the student. The model judges; code does the arithmetic and the checks.

The pipeline, stage by stage

1. Marking scheme (once per question, cached in rubrics/)

Job: turn the question and model answer into a short list of checkable points with marks that add up to the total. If the teacher supplies a rubric (RiceChem), it is used as is.
Why: grading a long answer against a long paragraph is vague; grading against 3 to 6 named points is checkable and the same for every student. Written once by a strong model (Sonnet) because a bad scheme hurts every answer, and it costs almost nothing when spread over many answers.
Variants: sized (default), atomic (model answer split into single claims), lenient / moderate / harsh, official.
↓

2. Read first (model, one call)

Job: read the student answer alone: what it says, the separate ideas, anything wrong or unclear, and its form (explanation, short answer, keyword list, incoherent).
Why: reading before seeing the scheme stops the marker hunting for expected words. The form feeds the gate in stage 4.
↓

3. Mark each point (model, one call)

Job: for every scheme point, say met, partial or not_met and quote the student's exact words as evidence.
Why: the model only decides what the student achieved. Code then prices it: met = full marks, partial = 0.9 of the marks (a setting), not_met = 0. One knob controls generosity, and the marks always match the verdicts the feedback is built from.
↓

4. Checks in code (no model)

  • Quote check: every quote must really appear in the answer, otherwise the point is flagged unverified_quote.
  • Form gate: scrambled text gets 0. A bare keyword list gets at most half marks, but only when the question asks to explain.
  • Deductions: if the teacher's scheme lists errors that cost marks, they are quote-checked and subtracted (floor 0). Off by default.
Why: these are cheap, certain and impossible for a model to talk its way around. The student text is treated as data, never as instructions.
↓

5. Cascade (optional, off by default)

Job: a cheap model (Haiku) marks every answer. If the marking looks unsure, a stronger model (Sonnet) marks that answer again and its marking replaces the cheap one. Unsure means: some point is partial, the total is neither near 0 nor near full, or a deduction was applied.
Why: the hard calls are partial credit and mid-range answers; clear full-mark and zero-mark answers are easy for any model.
↓

6. Feedback (model, one call; none for full marks)

Job: formal register: what the question asks, what the student got right (quoted), what was partly there, missed or incorrect and why, then what to improve.
Why: built from the verdicts so it cannot contradict the marks. A full-mark answer gets feedback built by code with no model call. A draft over 240 words is rewritten once.

The cascade: does it hurt?

Yes, on some answers; overall it helps. Sonnet is closer to the teacher on average, not on every answer, so re-marking can make a few answers worse. On SAF, re-marking mid-range answers moved Haiku-low from 0.127 to 0.137 error, because Haiku was already as good as Sonnet there. Averaged over three datasets it lowered error.

Cost: it is always more than Haiku alone (every answer is marked by Haiku, and the unsure share is marked again by Sonnet) and less than Sonnet alone. Sonnet costs about 14 times Haiku per answer.

Where the code is

Files
  • src/autograde/pipeline/rubric.py stage 1; read.py stage 2; grade.py stage 3; verify.py stage 4; cascade.py stage 5; feedback.py stage 6; run.py ties them together.
  • src/autograde/prompts/ every prompt, one Markdown file each. rubrics/ every saved marking scheme.
  • configs/*.yaml settings. DESIGN.md the full reasoning and every experiment.
Commands you will use
  • autograde run --dataset saf --split dev -n 40 --name myrun grade and score against the teacher.
  • autograde history every logged run. autograde cascade --cheap A --strong B free what-if from two finished runs.
